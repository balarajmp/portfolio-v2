### 3. Architecture Decisions Made
1. **Decoupled Data Layer:** The UI consumes interfaces from `@/types` and datasets from `@/content` via `@/config`. The application remains completely indifferent to whether data originates from static arrays, headless CMS APIs, or dynamic databases.
2. **Immutable Readonly Contracts:** All properties are specified as `readonly` or `ReadonlyArray<T>` to guarantee state immutability across the application lifecycle.
3. **Zero `any` Allowance:** Every contract utilizes strict primitives, enums, or nested sub-interfaces.
4. **Content-First Proof of Work:** The `Skill` contract explicitly references `verifiedProjectIds`, allowing UI components to automatically link technical skills to real project case studies.

---

### 4. Future Expansion Possibilities
- **Headless CMS Integration:** Easily swap static array exports in `src/content/` with fetch adapters calling Contentful, Sanity, or Strapi.
- **Dynamic MDX Engine:** The `BlogPost` content property seamlessly maps to local `.mdx` files or remote CMS responses.
- **Live Telemetry & GitHub API:** The `CodingProfile` contract supports background cron jobs syncing live LeetCode solved counts and GitHub contribution graphs.
